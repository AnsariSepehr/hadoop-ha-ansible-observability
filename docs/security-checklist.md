# Security checklist before publishing

[← Documentation index](README.md)

This repository is meant to be public, and so is any fork or deployment copy you make from it. Treat every item as required before the first push. `bash scripts/tools/check-secrets.sh` automates the pattern checks (private IPs, keys, long random strings, assigned passwords, and anything in your git-ignored `.forbidden-terms`).

| \#  | Check                                                                                                                                   | Why                                                                                                             | Done |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------------------|------|
| 1   | Replace every real host name, domain, realm name and IP address in configuration and screenshots with the placeholders from [Environment, prerequisites and masking conventions, 3.1](prerequisites.md#masking-legend) | They reveal the internal layout                                                                                 | ☐    |
| 2   | Never commit or share the `.generated/` folder (SSH key, certificates, cached facts). It is git-ignored; do not zip the working tree                                      | The archive contains the private SSH key used for NameNode fencing. Anyone holding it can log in to the cluster | ☐    |
| 3   | Regenerate the SSH key pair and redistribute the public key                                                                             | The current key left the control node inside an archive                                                         | ☐    |
| 4   | Rotate the Grafana admin password                                                                                                       | It is written in plain text in the stack file                                                                   | ☐    |
| 5   | Rotate the Keycloak client secret for the grafana client                                                                                | It is written in plain text in the stack file                                                                   | ☐    |
| 6   | Use Docker Swarm secrets for both (already how the stack file in this repository works)                                                                        | Environment values show in docker inspect and in the stack file                                                 | ☐    |
| 7   | Confirm secrets.yml is encrypted before every commit and the vault password is never committed                                          | The file holds every service password                                                                           | ☐    |
| 8   | Rotate any password that was ever stored unencrypted in secrets.yml                                                                     | A secret removed in a later commit is still in history                                                          | ☐    |
| 9   | Never commit the Kubernetes token file or the TLS keystores                                                                             | They give access to the API server and to Hadoop web traffic                                                    | ☐    |
| 10  | Commit sanitised copies of prometheus.yml and the stack file with \<SECRET\> placeholders                                               | Real addresses and tokens must not reach the repository                                                         | ☐    |
| 11  | Scan the working tree and the full git history with a secret scanner                                                                    | Finds what manual review misses                                                                                 | ☐    |
| 12  | Open JMX and exporter ports only to the monitoring node (manage_firewall: true)                                                         | Metrics reveal versions, paths and topology                                                                     | ☐    |
| 13  | Restrict who can sign in to Zeppelin with a Keycloak group or role                                                                      | Every allowed user can run code as the zeppelin account                                                         | ☐    |
| 14  | Replace self-signed Hadoop certificates with company CA certificates                                                                    | Removes browser warnings and the need to trust each node                                                        | ☐    |
