# Fixes for intermittent ZooKeeper / HDFS HA bootstrap

## Root causes addressed

1. ZooKeeper was managed by systemd as `Type=forking` while relying on a PID-file path that is not guaranteed to match the PID file used by `zkServer.sh` in every environment. This can cause systemd to mis-detect startup success/failure. The unit now uses `Type=simple` and `zkServer.sh start-foreground`, so systemd supervises the actual server process; the guessed PID file dependency is removed.
2. ZooKeeper quorum verification previously counted `standalone` as an acceptable leader. In a multi-node ensemble this can mask a node that started without forming the intended quorum. Verification now requires exactly one `leader` and only `leader`/`follower`/`observer` roles across the ensemble.
3. The HDFS active-NameNode wait task had `retries` and `delay` but no explicit `until`. It now retries until the active-state probe succeeds, rather than relying on implicit Ansible retry semantics.
4. ZooKeeper cleanup now removes its tmpfiles configuration and runtime directory as well as its service/config/data paths.

## Duplicate legacy Hadoop systemd units

The role retires the old unprefixed `journalnode.service` and
`namenode.service` units before installing canonical `hadoop-*.service`
units. It verifies `MainPID=0`, neutralizes the legacy ExecStop command, then
disables/removes the duplicate and reloads systemd. If a legacy unit still
owns a process, the play fails closed rather than risking an outage. Generic
daemon recovery no longer removes Hadoop `in_use.lock` files.


## Hadoop daemon lifecycle and data-safety corrections

- Common Hadoop service health now verifies both `systemd` state and the daemon's TCP listener. NameNodes are checked on their RPC port too; a standby NameNode still listens for RPC requests.
- ZKFC uses the configurable `hdfs_zkfc_rpc_port` and waits on the node's advertised address, not loopback.
- Removed custom `ExecStop=/bin/kill -TERM $MAINPID` commands. systemd now uses its normal process supervision and SIGTERM handling, avoiding `kill: not enough arguments` when `MAINPID` is empty.
- Removed ZooKeeper's global `pkill` from `ExecStartPre`; starting one ensemble member must not kill an unrelated ZooKeeper process.
- Recovery terminates only the matching Hadoop JVM and waits for its port to be released before starting a replacement.
- HDFS bootstrap refuses to format over an existing JournalNode namespace when NameNode metadata is missing, and refuses to erase unrecognised primary or standby NameNode contents without explicit full-reformat confirmation.

## MySQL safety corrections

- An uninitialised MySQL data directory containing files now fails closed instead of being automatically wiped.
- `mysql_force_reinit=true` now correctly forces initialization after the guarded wipe; the initialization decision is recomputed in the same run.
- Removed recursive rewriting of arbitrary MySQL configuration files under `/etc`; only the project-managed Group Replication config is removed during initialization.
- Removed `RESET MASTER` from Group Replication bootstrap/join flows so routine deployment and outage recovery preserve GTID/binlog history.
- Normal installation refuses to silently re-bootstrap an existing configured Group Replication node when no member is ONLINE. The explicit outage-recovery playbook opts into that operation after the operator selects `bootstrap_host`.
